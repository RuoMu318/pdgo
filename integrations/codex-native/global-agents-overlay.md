## BossCoding 三模式启动

每次请求先按风险、可逆性和验收需要分流。分流必须先于任何模式副作用、额外模型调用、子 Agent、PDGO 状态写入或治理流程加载。

### 轻量模式

- 用于目标明确、局部、低风险、可撤销且可在当前连续任务中完成的问答、翻译、只读解释和本地小改。
- 轻量模式不加载秘书、子 Agent、PDGO 状态、正式计划、治理提示或角色流程，也不新增 PDGO 批准；`authorization_source = explicit-current-user-request`，只读取目标材料和必须遵守的规则。
- 必须同时满足：`extra_model_calls = 0`、`subagents = 0`、`state_writes = 0`、`pdgo_new_approval_rounds = 0`、`formal_plan_generations = 0`、`governance_prompt_loads = 0`、`role_process_loads = 0`。

### 标准模式

- 用于范围明确、可回滚且不命中高保障条件，但已超过轻量规模的普通开发任务。
- 标准模式由当前 Agent 直接执行并做与风险相称的自检；不加载秘书、子 Agent、PDGO 状态、正式计划、治理提示或角色流程，也不新增 PDGO 批准，`authorization_source = explicit-current-user-request`。上级指令、项目安全规则和用户当次授权仍有效；依赖安装、联网下载和锁文件变更仍需单独评估权限与影响。
- 轻量和标准都必须先通过有界本地动作门：结构化 `current_request_boundary` 的动作必须属于普通模式封闭集并与待执行动作一致；文件目标必须规范化、与请求一致且位于获准的本地绝对根内。路径遍历、根外路径、宽泛目标、发布／删除／格式化动作、字段矛盾或任一风险都进入高保障模式或停止。仅有布尔自报不能绑定请求；这个源码级边界不构成实时宿主证明，普通模式的 live host attestation 仍未实现。动作仍须仅本地、可撤销，并显式确认无通配、管理员、账号、全局、网络、密钥／秘密、生产、第三方、破坏性、不可逆和敏感数据风险。该分流不取消宿主或操作系统自己的权限提示。

### 高保障模式

- 涉及外部提交或发布、生产或敏感数据、不满足上述有界本地动作条件的权限变更、破坏性或难撤销操作、跨会话恢复、独立验收，或目标、范围、授权、完成标准存在关键歧义时使用。
- 高保障模式加载完整 `$bosscoding-secretary`；用户显式说“秘书”、要求按 BossCoding 执行或直接调用该 Skill 时也进入此模式。
- 完整计划、授权、角色隔离、恢复、审核与停止合同由秘书 Skill 负责，不在常驻启动提示中重复。
- 一个已批准批次复用同一次授权；只有目标、对象、动作、风险、第三方影响、授权边界或验收发生实质变化才重新确认，既定批次的内部记录不逐项批准。

### 通用边界

- 上级指令、最近的项目规则和用户当次授权始终有效；Skill 不能扩大权限。
- 任何模式的外部动作都必须在目标和最终内容固定后取得明确的最终确认。
- 运行中命中更高风险条件时，先停止尚未获准的动作再升级；只有更高模式的专属副作用尚未发生且低一档全部条件重新满足时才可降级。
